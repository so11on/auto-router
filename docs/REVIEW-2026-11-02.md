# Review of 2026-11-02 and what is left

An evaluation made after the first real install, written so the next person can pick up where it stopped. See `docs/INCIDENTS.md` for the causes
and the fixes; this file is the assessment and the suggestions.

## What the gateway really gains (honest)
With the conversation kept on Claude, the gain of routing is **moderate and must be measured**:
- Most of it can be had by habit: Sonnet as the default, Opus on demand, `/effort`, Haiku subagents for verbose work, `/clear` between tasks.
- What only a gateway does automatically: (1) the right **effort per prompt** (thinking is the biggest output cost); (2) Haiku for simple questions
  at the start of a session, when no cache is lost; (3) protecting the 5-hour and weekly windows by going down a step when the pace says they will
  run out; (4) waiting for the reset and resuming the session; (5) spending **expiring Gemini credits** where Gemini is good (reading big things),
  money that would otherwise be lost; (6) a log and a report.
- Costs and risks: one more process between the client and the provider (if it dies the client stops: `ar.mjs off` is the way back); a model switch
  breaks the prompt cache of the model left; maintenance whenever Claude Code changes.
- How to decide: run in `shadow`, read `node ar.mjs report --since 7d`, compare the estimated saving and the cache-hit line with what the manual
  habits above would give. Go to `route` when it is clearly better.

## What Gemini is good and cheap for here (`gemini_tasks`)
Reading large inputs (1M tokens) and returning a summary; PDF/image/audio/video; web research with sources; an independent review of a diff;
many small non-urgent jobs through the Batch API (half price, asynchronous). It is not used for the conversation: the translation loses thinking,
server tools, documents and the prompt cache.

## The older stack (LiteLLM + OmniRoute + bridge)
Kept as the optional feature `legacy_stack`, because Copilot Chat needs it. What the gateway still imports from `litellm/`: `classify_rules`, `dlp`,
`engine`, `policy`, `registry`, `safety`, `models.yaml` and the parts of `routing.yaml` named `task_adjust`, `effort_default`, `switching`.
Only `router_hook.py`, `config.yaml`, `quota.py`, `context.py`, `pool.py`, `claude-bridge/`, `docker-compose.yml`, `profiles/` and the OmniRoute
commands of `ar.mjs` serve the Docker stack alone. Path to remove Docker for good: move the shared modules to `core/`, add an OpenAI-format input
adapter to the gateway (Copilot Chat and Codex use that format; `translate_openai.py` already does half of it), then mark the Docker parts legacy and
delete them when the adapter covers both clients.

## Suggestions, in order
1. Use `shadow` for a week; read the report; then decide `route`.
2. Measure whether a change of `effort` alone keeps the prompt cache (`report`, cache-hit line, before and after).
3. Add a context-cache path for Gemini on big repeated prefixes; today a 300k-token request is billed in full.
4. Build 2C (a project card generated on demand) and the automatic batch offers (2D) only after the report shows they matter.
5. The older stack's `.env.example` and docs still describe Docker first; a split `docs/LEGACY.md` would help new readers.
6. Windows: no login service yet; the gateway can be started by hand (`python gateway/server.py`).
